# 중대성평가 모듈 — standalone 프로토타입

Smart ESG의 "중대성평가/이중중대성평가" 부분만 독립적으로 구현한 프론트엔드입니다.
설계 문서(v2.0~v2.6) 및 실제 이노디스 이슈풀(6차배포 39개)을 반영했습니다.

## 실행 방법

별도 빌드 과정 없이 정적 파일입니다. 로컬에서 확인하려면:

```bash
cd materiality-app
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

Vercel 등에 그대로 배포해도 동작합니다(정적 파일이므로 별도 서버 설정 불필요).

## 화면 흐름

```
평가사이클 생성(연도) ─┬─▶ ESRS 토픽 마스터 (조회 전용, v2.0 2장)
                      ├─▶ 이해관계자 등록 (v2.0 2-3장)
                      ├─▶ 이슈풀 관리 (v2.4)
                      └─▶ 설문지 작성(16/24/39 프리셋) → 설문 응답(모의, 등록된 이해관계자 선택 가능)
                                                        → 결과 분석
                                                        → 사사분위 매트릭스(+수동조정, 사유 필수)
                                                        → 내부 IRO 정밀화 워크시트
                                                            (assessment_id·theme_group별 기록,
                                                             기본중대 토픽 비중대 판정 시 사유 강제)
                          평가사이클 확정(FINALIZED) → 이후 해당 사이클의 모든 점수/워크시트 잠김
                          다음 연도로 이월(Carry-forward) → 사유 입력 필수, 워크시트 참고값 복제
```

## v1(이슈풀만) → v2(이번 버전) 변경 요약

이전 버전은 v2.4(이슈풀)·v2.2(수동조정)·v2.6(IRO 워크시트)만 구현되고, v2.0에서 설계한
근간 구조(ESRS 토픽 마스터, 평가사이클, 이해관계자 마스터, 감사대응 강제요건)가 빠져 있었습니다.
이번에 아래를 추가로 구현했습니다.

- **ESRS 토픽 마스터**(`#/esrs-topics`): ESRS 1 AR16 10개 토픽, 기본중대(기후변화) 표시, 테마그룹 연결 현황
- **평가사이클 관리**(`#/assessments`): 연도별 사이클 생성/확정(FINALIZED)/다음 연도 이월(Carry-forward, 사유 필수)
- **이해관계자 마스터**(`#/stakeholders`): 등록형 이해관계자 관리, 설문 응답 시 선택하면 이름·그룹 자동입력
- **감사대응 강제요건**: 기본중대 토픽을 낮은 점수로 판정 시 별도 사유 입력 강제, 확정된 사이클은 모든 수정(수동조정·워크시트) 차단
- 설문지·매트릭스·수동조정·워크시트가 전부 평가사이클(연도)에 귀속되도록 데이터 구조 변경

## 파일 구조 및 향후 Supabase 연동 포인트

## 알려진 제한사항 (설계 문서에서 이미 명시된 것)

- **테마그룹 매칭은 추정안입니다.** `js/seed-data.js`의 `theme_group` 값 중 특히
  `WATER_WASTE_CHEM`/`QUALITY`/`CERT_PROCESS`/`ETHICS_ESG_FINANCE`는 영향/재무 이슈 개수가
  서로 맞지 않아 확인이 필요합니다(설계문서 v2.4 3장 참고).
- 짝이 없는 이슈(지역환경/지역사회/인권/기술경쟁력·국산화)는 매트릭스가 아니라
  "단일축 이슈" 목록으로 별도 표시됩니다(v2.4 4장 옵션 A 채택).
- 지금은 로그인/권한 체크가 없습니다 — 내부 IRO 워크시트(`#/iro/...`)는 실제로는
  ESG팀 전용이어야 하므로(v2.6), Smart ESG 본체와 연동 시 S-01 권한관리와 연결 필요.
- localStorage 기반이라 브라우저/기기 간 데이터가 공유되지 않습니다(의도된 프로토타입 한계).

## 테스트

Playwright로 아래 시나리오를 자동화 검증했습니다: 이슈풀 조회 → 설문지 발행(16문항 프리셋)
→ 8명 모의 응답 제출 → 분석 화면 → 매트릭스 렌더링 → 점 클릭 상세 → 수동조정
(사유 누락 시 저장 차단 검증 포함) → 조정 반영 확인 → 계산값 복원 → 내부 IRO 워크시트 저장,
그리고 39개 전체 선택 시 단일축 이슈 4건이 정확히 분리 표시되는지까지 확인했습니다.

## v2(평가사이클) → v3(이번 버전) 추가 기능

타사 사례(하나머티리얼즈, PI첨단소재 이중중대성평가 보고서) 검토 후 반영:
- 매트릭스에 **GRI 코드**, **E/S/G 분야**, **High/Medium/Low 등급** 표기
- **중대이슈 결과표**(순위/분야/중대이슈/Financial/Impact/GRI/전년비교) — 매트릭스 화면 하단에 자동 생성
- 평가사이클 확정 시 **이중중대 이슈 스냅샷 저장** → 다음 연도 확정 시 자동으로 New/Existing 배지 표시

사용자 편의 기능(요청 반영):
- **선택 개수 제한**: 목표 문항수를 정하면 그 이상 체크 불가(경고 표시), Playwright로 "8번 시도해도 정확히 5개에서 멈춤" 검증 완료
- **E/S/G 균등선택**: 목표 문항수를 환경/사회/지배구조 3개 축에 최대한 균등 배분해 자동 선택
- **랜덤 선택**: 이슈풀에서 목표 개수만큼 무작위 선택(Fisher-Yates shuffle)
- **구글폼으로 내보내기**: 선택한 문항을 Google Apps Script(.gs) 코드로 다운로드 → script.google.com에 붙여넣고 실행하면 실제 구글폼이 자동 생성됨(공식 REST API로는 폼을 직접 만들 수 없어 Apps Script 방식을 사용). 다운로드된 스크립트에 FormApp.create 및 문항 수만큼 addScaleItem이 포함되는지 검증 완료
- **엑셀 일괄 업로드**: 발행된 설문에 맞춘 응답 템플릿(.xlsx)을 다운로드 → 오프라인/대량 응답을 엑셀로 채워 업로드하면 일괄 반영. 로컬 번들된 SheetJS(`js/vendor/xlsx.full.min.js`)로 처리하므로 외부 CDN 의존 없음. 실제 다운로드→작성(openpyxl)→업로드 왕복까지 자동화 테스트로 검증 완료
- **관리자 배점·가중치 조정**(`#/weights/:assessmentId`): 이해관계자 그룹별 응답 가중치(가중평균), 영향/재무중대성 임계값을 평가사이클 단위로 조정 가능. 매트릭스·분석 화면에 즉시 반영

## 알려진 제한사항 (v3 추가분)

- 엑셀 업로드 템플릿의 헤더는 issue_code(예: ISS-01)로 매칭됩니다 — 업로드 파일의 헤더를 임의로 바꾸면 매칭되지 않습니다. 반드시 "엑셀 템플릿 다운로드"로 받은 양식을 사용하세요.
- 구글폼 변환은 Google의 공식 REST API 제약상 Apps Script 코드 생성 방식입니다. 실행하려면 사용자가 script.google.com에서 직접 실행해야 하며, 앱에서 자동으로 폼이 생성되지는 않습니다.
- 전년대비 New/Existing 비교는 같은 브라우저(localStorage)에 직전 연도가 FINALIZED 상태로 존재할 때만 동작합니다.
